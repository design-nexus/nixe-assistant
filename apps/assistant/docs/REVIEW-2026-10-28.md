# Assistant review — 2026-10-28

Reviewed baseline: `7f3d7a8`. This is an audit, not approval to change models, defaults, or add dependencies.

## Scope and current health

Reviewed the daemon's request routing, conversation and task lifecycle, streaming STT client, TTS/chunker and playback, inference/context budgeting, tool discovery, policy/grants, plugin workers and sandboxing, native desktop tools, browser worker, system diagnostics, proactive events, dictionary, Aura/Canvas, Settings integration, service units and installer. Source review does not establish every third-party application's runtime compatibility.

Live checks: daemon, visual service and STT service are active; the private status request reports **268 tools and no load errors**. Current TTS is **Kokoro / af_heart**; wake listening is enabled; desktop notifications are disabled. No model download, inference run, desktop action or application restart was performed for this audit.

## Findings, in recommended order

### 1. High: ordinary logs retain spoken content, including ignored wake speech

`daemon/nyx-assistantd/src/app.rs:1107,1499,1940–1955` logs transcripts, replies and speech that did not match the wake word at info level. The service sets `RUST_LOG=info`. `duplex.rs:372,503` also records recognized text, and `assistant-tools/src/agent.rs:127` logs the complete handoff command/prompt.

The in-memory conversation history is therefore not the only record of speech. With wake listening enabled, unrelated recognized speech can reach the system journal. This is source-confirmed; journal contents were not dumped during this audit.

**Change:** make content logging an explicit, temporary diagnostic option. Normal logs should retain timings, request IDs and error categories without utterances or prompts. Explain the remaining storage boundaries in Settings. Turning this off would not remove existing journal entries.

### 2. High: speech-error paths skip background-task cleanup

In `app.rs:1491`, a failed TTS worker returns through `?` before `barge.abort()` and `cancel_task.abort()`. In `app.rs:1528`, failed synthesis similarly exits before aborting the barge-in watcher. The caller reports an error and clears the busy flag, but does not cancel the turn token (`app.rs:821–827,1052`). Dropping a Tokio join handle detaches its task.

**Impact:** watchers can remain alive after a failed turn until a later cancellation, consuming audio events or interfering with subsequent listening. This is a control-flow finding; no production TTS failure was injected.

**Change:** use a turn-scoped cleanup guard that always cancels generation/watchers and clears failed playback, including early returns.

### 3. High: discovery alone can be reported as a completed task

`app.rs:2175–2183` injects a successful discovery result when the planner initially finishes without doing anything. On its next finish, this counts as a nonempty result list, even though no task step was recorded. `assistant-policy/src/task.rs:244–248` treats an empty step list as Completed, and `app.rs:2048` uses that outcome.

**Impact:** an unsupported or unfulfilled request can produce a completed task and confirmation event after only looking up tool definitions. The action-based protection later in the planner applies specifically to Computer requests.

**Change:** distinguish metadata discovery, useful read results and fulfilled requested actions. Require evidence appropriate to the request before calling it complete.

### 4. Medium: playback completion has a fixed 30-second ceiling

`assistant-audio/src/engine.rs:247–263` leaves `wait_playback()` after 30 seconds even if samples remain queued. Callers then finish speech and may arm follow-up listening.

**Impact:** a sufficiently long queued answer, stalled device or slow output can be marked finished while audio remains. The precise audible effect depends on the remaining queue; it was not reproduced with speakers.

**Change:** make completion cancellation-aware and based on actual playback progress. Treat a genuine output stall as an explicit error rather than successful completion.

### 5. Medium: sentence splitting still mishandles abbreviations and quotes

The actual `assistant-agent/src/chunker.rs:76` was compiled into a small temporary probe. It produced:

```
Ask Dr. Smith tomorrow. Then call me.
=> ["Ask Dr.", "Smith tomorrow.", "Then call me."]

The U.S. office is open. Come in.
=> ["The U.S.", "office is open.", "Come in."]

She said "hello." Then left.
=> one combined phrase
```

**Impact:** avoidable synthesis boundaries and inconsistent prosody remain despite the recent sentence-pacing improvement. This proves chunking behavior, not the sound of a newly synthesized sample.

**Change:** recognize common abbreviations/initials and closing quotation marks when deciding sentence boundaries. Preserve Kokoro and the existing pacing work.

### 6. Medium: bar charts silently change negative data to zero

`assistant-visual/src/main.rs:840–856` uses a zero-based LevelBar, clamps each value to `[0,max]`, and displays the clamped value as its label.

**Impact:** a value such as -5 becomes a bar and label of 0. That is incorrect output, particularly for temperature, balances and changes over time.

**Change:** render a signed axis using the existing plotting dependency, or reject unsupported negative data explicitly until supported. Never relabel the input value.

### 7. Medium: Canvas opens for unrelated search tools

`assistant-visual/src/main.rs:1279` opens Canvas for any successful tool ending in `.search` with a nonempty `results` array. It does not check whether visual output was requested or useful.

**Impact:** voice-only searches can create a window and replace unpinned content. The same behavior can apply to future search plugins unrelated to web results.

**Change:** use an explicit visual-output decision or typed Canvas payload. Keep spoken-only lookups in the voice interface by default.

### 8. Medium: Aura does not synchronize state on connection/reconnection

`assistant-visual/src/main.rs:1221–1238` connects and only reads future events. It does not request current state, session, approvals or running settings. The IPC server also does not send an initial snapshot (`assistant-ipc/src/server.rs:73–115`).

**Impact:** starting/reconnecting the visual process in the middle of a turn can leave it showing idle or stale configuration until another relevant event arrives. Outstanding approval attention can be missed visually; the separate approval UI remains available.

**Change:** request a correlated initial snapshot on every connection and reconcile it with subsequent events.

### 9. Medium: tool discovery consumes the small action budget

The running configuration allows four calls per task. Both explicit discovery and the automatic discovery retry count against it (`app.rs:2181,2236`). Four always-included definitions also occupy approximately 4 KB of the 10 KB schema selection on this installation.

**Impact:** a task needing discovery plus several legitimate steps can stop before finishing. Increasing every task's budget would also increase opportunities for accidental actions.

**Change:** give metadata discovery its own small bounded allowance. Keep action/time limits and the compact working catalog. Tune selection before expanding prompts.

### 10. Medium: Aura still performs work continuously while idle

`assistant-visual/src/main.rs:1321–1339` wakes the GTK event poll every 40 ms and runs three `hyprctl` subprocesses per monitor snapshot every 600 ms, including while Aura is invisible. These subprocesses have no deadline (`main.rs:91–100`).

**Impact:** avoidable process churn and wakeups; a stuck command stops monitor refresh. Invisible drawing already stops, so this is a remaining efficiency issue rather than a claim that idle rendering is continuously drawing.

**Change:** use compositor events and the existing native IPC client, bounded queries, and less frequent reconciliation. Keep GTK work driven by arriving events/frame clocks.

Additional source-visible limitations: primary display means the first returned monitor (`main.rs:144`); system reduced motion is captured only at startup; multiple monitor tick callbacks advance one shared animator clock. These need attention before claiming complete multi-monitor support. A second physical monitor was not available.

### 11. Medium: Canvas can block Aura while opening/rendering content

Canvas and Aura share the GTK main thread. Document reads occur synchronously (`main.rs:869`), and PDFs open and render synchronously on that thread (`main.rs:1166–1218`). File size limits do not bound PDF rendering complexity or image decoded dimensions.

**Impact:** sufficiently expensive content can delay Aura updates and input in Canvas. This is a source-level responsiveness risk; no hostile or oversized media was opened.

**Change:** move expensive loading/decoding to bounded workers, cache rendered PDF pages, and report loading/failure locally. Retain the established media libraries.

### 12. Medium: unknown handoff providers silently become Antigravity

`assistant-tools/src/agent.rs:44–45` maps any unknown provider to `agy`. The handoff is an interactive terminal launcher, not a managed noninteractive delegation with authentication checks, captured results and Nixe-controlled delegated tool grants.

**Impact:** a misspoken/unsupported provider can select a different external provider. Listing installed CLIs is not equivalent to the planned managed delegation. Hermes here is a launcher entry, not a replacement agent architecture.

**Change:** reject unknown/uninstalled providers explicitly. Keep terminal launching clearly labeled. Treat managed frontier delegation as unfinished work requiring a narrow adapter and explicit external authorization.

### 13. Lower priority: retention and restart continuity remain incomplete

Conversation history is bounded to 100 pairs in RAM (`app.rs:1139`), but searchable persisted conversation history and resumable tasks across restart are not implemented. Startup marks interrupted tasks failed (`assistant-policy/src/store.rs:132–139`). Existing dictionary and saved project/notes data are separate working features.

File undo backups (`assistant-tools/src/fs.rs:252`) and audit/task tables lack an implemented age/size pruning policy. The 100-entry action list does not prune corresponding file backups. This can accumulate disk usage and retain deleted content in undo storage.

**Change:** add explicit retention/review/deletion controls first. If resumable tasks are added, restore a checkpoint and revalidate the environment and approvals before any effect; never replay mutations automatically.

## What should stay

- Keep Gemma and Kokoro af_heart. This audit provides no evidence supporting a model migration.
- Keep the native desktop interfaces, argument-bound grants, schema validation, separate privileged helper and existing sandbox boundaries.
- Keep bounded tool discovery rather than placing all 268 schemas into every prompt.
- Keep dictionary learning based on explicit corrections and confirmation; do not learn model guesses automatically.
- Keep Aura and Canvas distinct; improve their lifecycle and responsiveness rather than rebuilding them.
- Keep external delegation optional and desktop notifications disabled.

## Recommended delivery order

1. Content-log privacy, guaranteed turn cleanup, truthful task completion and playback completion.
2. Sentence boundary handling, signed charts, explicit Canvas opening and visual state resynchronization.
3. Separate discovery allowance, event-driven Aura updates and bounded media loading.
4. Retention controls and clear handoff-provider validation; consider task checkpoints/searchable history afterward.

Useful additions: a capability-health view showing available/blocked/unhealthy tools and specific reasons, plus one compact failure record containing routing, tool selection and timing without utterance content. Maintain a small regression set of paraphrased voice/Canvas requests to catch false capability refusals. Avoid adding another inference or orchestration dependency to solve these issues.

## Validation limits

Performed read-only runtime health checks, inspected recent warning/error categories, reviewed source/configuration paths, and compiled/executed the actual chunker in a temporary standalone probe. No broad test suite or inference benchmark was run. Physical microphone interruption, multi-monitor behavior, fullscreen/scaling, long playback, injected synthesis failures and expensive-media responsiveness remain untested in this review. No runtime code, settings, installed files or running processes were changed.
